# Two-player co-op game intro

Use when the video begins as a two-player game menu, configures both players, confirms a shared setup, loads the world, and transitions into co-op play.

## Lock identity and UI before motion

Confirm visual style, game title, Player 1 name, Player 2 name, exact UI copy, ratio, duration, and optional identity references. Assign stable screen sides, body contrast, outfit/equipment colors, player-card positions, menu hierarchy, palette of roughly five coordinated colors, typography weight, and one confirmed first-frame/menu composition.

Identity references transfer recognizable face silhouette, hairstyle, glasses, proportions, and distinctive traits; they do not force photographic lighting or realism when the selected game style differs. Never swap player names, faces, positions, body types, colors, or equipment roles.

## Fifteen-second event framework

Adapt rather than blindly copy this official structure:

- 0–2s: high-angle two-player main menu; both characters breathe/blink; exact player cards and menu copy are readable.
- 2–4s: camera moves to Player 1; lightweight/precise equipment UI and transformation.
- 4–7s: camera crosses to Player 2; clearly contrasting heavy/power equipment UI and transformation.
- 7–8.5s: return to two-shot; shared confirmation button; synchronized readiness gesture.
- 8.5–10s: shared loading bar; menu environment continuously transforms into the game world.
- 10–15s: camera lowers behind the pair into a stable third-person co-op view; HUD, player states, task marker, environment ambience, and forward movement appear.

If the requested concept or duration differs, preserve the causal chain—menu → separate configuration → shared confirmation → continuous world load → co-op entry—while retiming it.

## Prompt controls

- Make the approved menu image a layout/UI reference, and keep player identity references separate.
- Repeat exact usernames and UI strings in the shot where they appear. Reduce text load when legibility is fragile.
- Maintain one palette and UI surface language across buttons, cards, load bar, HUD, icons, and equipment.
- Use continuous camera and transformation logic unless the user requests cuts. Keep the non-focused player visible or explicitly track their off-screen state.
- Describe synchronized UI hover/click, mechanical locks, energy confirmation, loading rise, ambience transition, footsteps, and HUD cues.

## Audit

Check two and only two principal players, correct side/name/identity mapping, distinct proportions/equipment, readable approved UI copy, no copied commercial game logo or interface, no unexpected extra menu items, continuous world transformation, and a stable final co-op viewpoint.
